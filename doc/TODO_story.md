## B. 대화

### B1. 클라이언트 대화 UI

- [x] **B1-1.** 대화 창과 그 앞뒤 배관을 붙였다. 서버가 보낸 노드를 그리고, 고른 번호를
      그대로 돌려보낸다.

      | 파일 | 역할 |
      | --- | --- |
      | `Scripts/UI/DialogWindow.cs` | 창(코드로 만든다 — 프리팹/씬 배치 없음) |
      | `Scripts/Dialog/DialogController.cs` | 상호작용 → 노드 표시 → 선택 회신. Session 의 역할 객체 |
      | `Scripts/PacketFactory.cs` | `CreateInteractMessage` / `CreateDialogSelectMessage` |
      | `Scripts/Session.cs` | `DialogNode` 수신 분기, `Interact()`, 가장 가까운 NPC 에게 말 걸기 |
      | `Scripts/GameData/ResourceLoader.Localization.cs` | text_id → 문장 (새로 붙임) |

      **창을 씬이 아니라 코드로 만든다.** 대화는 어느 맵에서나 필요한데 게이트로 씬이
      바뀌므로, 씬에 배치하면 네 개 씬에 같은 것을 두고 계속 맞춰야 한다.
      `DamageTextManager` 와 같은 방식으로 처음 필요할 때 만들고 씬 전환에도 유지한다.

      **로컬라이즈 표가 클라에 없었다.** 데이터는 `text_id` 만 담고 문장은 로컬라이즈
      파일에 있는데, 클라가 그 파일을 읽는 코드가 없어 창을 붙여도 `dlg_rinne_greet` 이
      그대로 보일 상황이었다. 표는 `{ "키": "문장" }` 평평한 객체라 테이블 로더(생성 코드)를
      타지 않으므로 손으로 쓰는 쪽(`ResourceLoader.Localization.cs`)에 두었다.
      키가 없으면 키를 그대로 보여 준다 — 빈칸이면 "문장이 없다"와 "키가 틀렸다"를 구분할 수 없다.

      **NPC 를 누르는 대신 F 키로 말을 건다.** 씬에 NPC 오브젝트가 아직 없어 누를 대상이
      없다(A1-Unity 와 같은 문제다). `npc.json` 의 좌표로 지금 맵에서 상호작용 거리 안의
      가장 가까운 NPC 를 찾아 같은 `Interact` 를 보낸다 — 서버도 데이터 좌표로 거리를 재므로
      판정은 같다. 씬에 NPC 가 생기면 클릭에서 `Session.Interact(npcId)` 를 부르면 된다.

      컴파일은 확인했다(`Client/Assembly-CSharp.csproj` 빌드, 에러 0 / 새 파일 경고 0).
      화면에 실제로 어떻게 보이는지는 에디터에서 봐야 한다 → E4.

## F. 데이터 전수 점검 (2026-08-31)

> `GameDataFlow.py` 검증은 0 에러로 통과하는 상태에서, **검증이 잡지 못하는 내용상의 구멍**을
> 스크립트로 훑어 찾은 것들이다. 잡는 방법을 아는 것은 그때그때 검증 규칙으로 옮긴다.

### F1. 진행이 막히는 것

- [x] **F1-1 · F1-2. 선택 보상 퀘스트를 대화로 끝낼 수 없었다.** 둘은 뿌리가 하나다 —
      대화 응답에는 보상 번호를 실을 자리가 없어서, `PlayerDialog` 가 번호 없이 부르고
      `PlayerQuest::CompleteQuest` 가 그것을 거절했다. 그래서 **11003(3203) · 11006(3402) ·
      11008(3401)** 의 완료 선택지는 화면에 보이는데 눌러도 아무 일도 일어나지 않았고,
      1001 은 그 선택지가 아예 만들어지지 않아 **메인 체인 10 의 입구가 처음부터 막혀
      있었다**(히스토리를 봐도 한 번도 있던 적이 없다).

      **선택지 자체가 보상을 정하게 했다.** 완료 선택지를 보상마다 하나씩 두고 각각에
      0-based `reward_choice` 를 적는다. 프로토콜도 클라 UI 도 건드리지 않고, NPC 에게
      "검으로 주세요 / 방패로 주세요"라고 말하는 모양이 되어 대화로서도 자연스럽다.

      | 바꾼 곳 | 내용 |
      | --- | --- |
      | `dialog.json` | 1001 의 완료 선택지 신설(검/방패), 11003 · 11006 · 11008 은 하나를 둘로 |
      | `PlayerDialog::applyAction` | `CompleteQuest(param, choice.reward_choice)` |
      | 스키마 | `reward_choice` 는 데이터에서 추론되어 C++/C# 양쪽에 자동으로 생겼다 |
      | 봇 | `QuestComplete` 직접 전송을 걷어내고 대화 경로로 통일(자기 몫의 선택지를 고른다) |

      **검증 규칙 둘을 새로 넣었다.** ① 선택 보상 퀘스트의 완료 선택지는 보상마다 하나씩
      있어야 한다(번호 누락 · 범위 밖 · 중복 · 빠진 보상 · 선택 보상 없는데 번호를 적은 것).
      ② 기존 "받을 수 있는가"(B0-2)를 **"받고 끝낼 수 있는가"**로 넓혔다 — `end_npc_id` 의
      대화에 `complete_quest` 가 없으면 오류다(자동 완료 퀘스트는 제외). 데이터를 되돌려
      보면 다섯 경우 모두 그대로 잡아낸다.

      회귀 테스트: `RewardChoiceIsDecidedByWhichCompleteChoiceIsTaken`(방패를 고르면 방패만
      들어온다), `EveryChoiceRewardQuestCanBeCompletedThroughItsDialog`(데이터 전수).

      숲 게이트를 레벨 20 으로 올리면 그 너머 퀘스트 16개가 한꺼번에 걸린다.

### F2. 설계 의도와 데이터가 어긋난 것

- [x] **F2-1. 11003 이 2단계 분기를 건너뛸 수 있었다.** 선행 조건이 `[11001]` 뿐이라
      11002/11009 중 아무것도 안 하고 받을 수 있었다 — 대화(3201 의 `completed` 조건)가
      막고 있을 뿐, `QuestAccept` 를 직접 보내면 통과했다. 선행 조건이 AND 만 지원해서 생긴
      타협이었다.

      **`prerequisites.completed_any_quest_ids` 를 넣었다** — "이 중 하나면 된다"(OR).
      11003 은 이제 `completed_quest_ids: [11001]` + `completed_any_quest_ids: [11002, 11009]`
      다. 양쪽 다 만족해야 하므로 가지를 하나는 반드시 지나야 하고, 어느 가지를 탔든
      다음 칸으로 이어진다.

      검증은 후보가 하나뿐인 경우(그냥 AND 다)와 같은 퀘스트를 양쪽에 적은 경우(AND 가 이겨
      OR 이 뜻을 잃는다)를 막는다. 회귀 테스트 `Accept_SkippingTheBranchAltogetherIsRejected`.

- [ ] **F2-2. 메인 체인 10 이 2칸에서 끊긴다.** 1001 → 1002 로 끝이고, 체인 101 은 8칸이다.
      봇이 "분기"로 고르는 두 체인의 분량이 4배 차이 난다. (콘텐츠 설계)

- [ ] **F2-3. 유니크 스폰 + 60초 재생성.** 11007 의 두목(10)과 11008 의 골렘(9)은 잿빛 숲에
      각 1마리뿐이다. E2 에서 잰 11007 578초가 여기서 나온다. 다인 환경에서는 경합도 붙는다.

### F3. 만들어 놨는데 보이지 않는 것

- [ ] **F3-1. 클라이언트에 퀘스트 UI 가 없다.** `Session.cs` 가 `QuestSync` 를 아예 받지 않는다.
      퀘스트 이름·설명·스테이지·목표 문구 **116개 로컬라이즈 키**가 화면에 나오는 곳이 없다.
      지금 로컬라이즈를 쓰는 것은 대화창뿐이다.

- [x] **F3-2. 로컬라이즈 키 누락** — 스토리 작업으로 새로 만든 것만 채워져 있었다.
      **38개를 ko/en 양쪽에 채웠다**: 몬스터 10종, 기본 아이템 5종(포션 3 · 검 · 방패,
      이름+설명), 맵 6곳(이름+설명, `story.md` 의 표기를 따랐다 — 세이린 항 · 바람고개 ·
      밭길 · 잿빛 숲 · 아르카디아 평원 · 하늘의 무덤), NPC 2003, 게임 모드 2종과 레이드
      보스 이름. NPC 2003 은 `dialog_id: 0` 이라 여전히 말을 걸 수는 없다(호위 전용이다).

      **검증에 넣었다** — 데이터가 쓰는 문구(값이 문자열인 `*_id` 필드)가 사전에 없으면
      오류다. 언어끼리 키가 어긋나는 것도 함께 본다(개발 언어로만 켜 보면 안 보인다).
      빠져도 게임을 켜기 전에는 아무 데서도 티가 나지 않는 종류의 구멍이라, 마지막 5개
      (`GameMode.json` 쪽)는 사람 눈이 아니라 이 규칙이 찾아냈다.

      > **스킬은 예외로 뒀다**(`LOCALIZATION_EXEMPT_TABLES`). 클라이언트가 스킬 이름을
      > 사전이 아니라 `name_id` 에서 "_name" 을 떼어 쓰기 때문에(`InputHandler`,
      > `GameInputManager`), 지금 이 표의 `name_id` 는 사전 키가 아니라 식별자에 가깝다.
      > 스킬 108개 문구를 제대로 넣기로 하면 그 예외부터 지운다 — 그때까지 화면에는
      > "armageddon" 같은 영문 식별자가 나온다.

      또한 **검증 메시지가 콘솔에서 터지던 것**을 함께 고쳤다. 메시지가 한국어라
      cp949 콘솔에서 `UnicodeEncodeError` 로 도구가 죽어, 정작 오류를 알려야 할 때
      아무것도 못 알려 줬다(`GameDataFlow.py` 에서 stdout 을 utf-8 로 맞춘다).

- [ ] **F3-3. 퀘스트가 스킬을 하나도 주지 않는다.** `rewards.skill_ids` 를 쓰는 퀘스트가 0개다.
      스킬 습득 경로는 `starter=true` 지급뿐이고 starter 는 평타·점프 둘뿐이라,
      skill.json 의 나머지 52개는 얻을 방법이 없다(화염구는 로컬라이즈까지 되어 있는데도).
