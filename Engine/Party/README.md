# 파티

여러 플레이어가 같은 사냥/퀘스트를 함께 진행하기 위한 시스템. 접속 중에만 존재하는
상태라 DB 에 남지 않는다 — 서버를 재시작하면 모든 파티는 사라진다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `Party.h` | 파티 하나(멤버 목록, 리더, 버전). 변경은 `PartyManager` 만 한다 |
| `PartyManager.h/.cpp` | 멤버십 규칙의 단일 출처. 플레이어를 **id 로만** 다룬다 |
| `PartyPolicy.h` | 최대 인원/제안 만료/킬 크레딧 반경/경험치 분배. 운영이 런타임에 바꾼다 |
| `PartyCredit.h/.cpp` | 처치 크레딧을 누가 받는지 정하고 이벤트를 발행한다 |
| `../Player/PlayerParty.h/.cpp` | 규칙을 실제 플레이어에 붙이는 층. 클라 동기화와 퀘스트 공유 |

### 왜 두 층인가

`PartyManager` 는 `Player` 도 `Character` 도 네트워크도 모른다. 덕분에 월드 없이 그대로
시험할 수 있고(`UnitTest/PartyTest.cpp` 의 절반이 그렇다), 반대로 "누구에게 무엇을
보낼지"는 전부 `PlayerParty` 에 모인다.

### 변경 통지는 밀지 않고 당긴다

파티가 바뀔 때 각 멤버에게 알림을 **밀어 주려면** 파티가 멤버의 포인터를 들고 있어야 하고,
그러면 접속 종료/재접속마다 죽은 포인터를 걱정해야 한다. 대신 `Party` 는 로스터가 바뀔
때마다 `version_` 만 올리고, 각 `PlayerParty` 가 자기 `Update` 에서 마지막으로 클라에
보낸 값과 비교한다. 파티가 해산되면 조회 결과가 `nullptr` 이 되므로 "파티에서 빠짐"도
같은 비교 하나로 잡힌다.

## 멤버십 규칙

- **초대는 수락 시점에 파티를 만든다.** 초대할 때 미리 만들면 거절당했을 때 혼자짜리
  파티가 남는다. 초대에 적힌 `party_id` 도 수락 시점에 다시 확인한다 — 그 사이 초대한
  쪽이 해산했거나 다른 파티에 들어갔을 수 있다.
- **파티가 있으면 리더만 부를 수 있다.** 아무나 부를 수 있으면 리더가 모르는 사이에 자리가
  차서, 정작 부르려던 사람을 못 부르게 된다.
- **한 사람이 동시에 들 수 있는 초대는 하나.** 두 개를 들고 있으면 "수락"이 어느 쪽인지
  모호해진다.
- **1명이 남으면 해산한다.** 혼자짜리 파티는 파티가 아닌 것과 같은데, 남겨 두면 "파티 중"
  이라 다른 파티의 초대도 거절된다.
- **리더가 나가면 남은 멤버 중 가장 오래된 쪽이 이어받는다.** 리더 없는 파티는 초대도
  추방도 못 하는 상태가 된다.
- **컴포넌트가 사라지면 파티에서도 빠진다.** `PlayerParty` 소멸자가 `RemovePlayer` 를
  부르므로 정상 종료/재접속 유예 만료/서버 정리 어느 경로로 사라져도 한 번은 정리된다.

## 킬 크레딧

`Monster::NotifyKilledBy` 는 "이 액터가 여기서 죽었다"까지만 알리고, 몇 사람이 나눠 갖는지는
`party_credit::PublishActorDead` 가 정한다.

크레딧 대상 = **킬러** + **같은 맵에서 반경 안에 살아 있는 파티원**.

- 같은 맵 조건은 `Map::FindPlayer` 조회로 자연히 걸러진다(다른 맵/인스턴스는 찾히지 않는다).
- 반경은 xz 평면에서만 잰다. 높이로 갈리면 다리 위아래 같은 지형에서 결과가 들쭉날쭉해진다.
- 마지막 일격을 넣은 쪽은 거리 조건 없이 받는다.
- 실제로 발행 가능한 대상만 세어 분배 인원수를 정한다. 빙의 전 캐릭터까지 세면 아무도 받지
  않은 몫만큼 남들의 경험치가 깎인다.

대상 전원의 `PlayerEventBroker` 로 `EventActorDead{ ..., credit_share = 인원수 }` 가 나간다.

| 받는 쪽 | 처리 |
| --- | --- |
| `PlayerQuest` | 인원과 무관하게 **각자 1마리로 센다**. 나눠 세면 파티 사냥이 퀘스트 진행에는 손해가 된다 |
| `PlayerLevel` | `PartyPolicy::ShareExp(base, credit_share)` 로 나눈다 |

### 경험치 분배

```text
총량   = base * (1 + bonus * (n - 1))     bonus 기본값 0.1
1인분  = 총량 / n                          (최소 1)
```

파티가 커질수록 총량은 늘지만 1인분은 줄어든다 — 나눠 먹는 대신 사냥 속도를 얻는 구조다.
보너스가 1인분 감소를 완전히 메우게 하면 혼자 하는 쪽이 손해가 되어 모두가 파티를 강요당한다.

## 퀘스트 공유

`quest.json` 의 `shareable` 이 참인 퀘스트만 공유할 수 있다. 공유하는 쪽은 그 퀘스트를
진행 중이어야 한다.

제안은 **강제 수락이 아니다**. 받는 쪽이 답할 때까지 `PlayerParty` 에 남아 있다가
`PartyPolicy::GetOfferTimeoutSec` 이 지나면 사라진다.

- 받을 수 없는 파티원(레벨 미달, 이미 진행/완료 등)에게는 창을 띄우지 않는다. 조건은
  실제 수락과 같은 `Quest::CanAccept` 를 본다.
- 답하지 않은 제안이 있으면 다른 공유가 덮어쓰지 않는다. 덮어쓰면 클라가 띄운 창과 서버가
  아는 제안이 어긋난다.
- 수락해도 조건 검사는 그대로 탄다. 제안을 받은 뒤 답하기까지 사이에 조건이 깨졌을 수 있다.

## 네트워크 프로토콜

| 메시지 | 방향 | 내용 |
| --- | --- | --- |
| `PartyInvite` | 양방향 | C→S 는 `actorId`(화면에서 고른 캐릭터), S→C 는 초대자와 남은 시간 |
| `PartyInviteReply` | C→S | 수락/거절 |
| `PartyLeave` | C→S | 탈퇴 |
| `PartyKick` | C→S | 추방(리더) |
| `PartyLeaderChange` | C→S | 리더 위임(리더) |
| `PartySync` | S→C | 로스터 전체. `partyId == 0` 이면 파티에 속해 있지 않다 |
| `PartyQuestShare` | 양방향 | C→S 는 `questId`, S→C 는 보낸 사람과 남은 시간 |
| `PartyQuestShareReply` | C→S | 수락/거절 |

초대 대상을 **이름이 아니라 `actorId` 로** 지정하는 이유는 이름이 유일하다는 보장이 없기
때문이다. 화면에서 고른 그 캐릭터가 그대로 대상이 되고, 서버는 그 액터가 정말 같은 맵의
캐릭터인지 확인한다.

탈퇴/추방/해산은 모두 `PartySync` 하나로 전달된다(사유별 메시지가 따로 없다). 클라는
`PartySync` 만 믿고 파티 창을 그리면 된다.

서버 → 클라 알림은 `PlayerParty::Update` 끝에서 컴포넌트가 직접 보낸다(전송 통로는
[`PlayerSender`](../Player/PlayerSender.h)). 이 Update 가 `Player::Update` 를 타고 **1초에
한 번** 돌기 때문에 초대 창이 뜨거나 파티 창이 갱신되기까지 최대 1초가 걸린다(퀘스트
동기화와 같은 주기다). 제안 만료 시간도 같은 틱에서 재므로 만료 판정 자체는 어긋나지 않는다.

로스터의 이름과 레벨은 상대의 `PlayerLevel` 컴포넌트에서 바로 읽는다 — 월드 조회가 필요
없으므로 세션 없이도 채워진다. `actorId`/`mapId` 만은 `Player → Character` 를 거쳐야 해서
소유 `Player` 가 있을 때만 채워지고, 없으면 0 이다.

## 운영(GM)

`PartyPolicy::Instance()` 로 서버 재시작 없이 바꾼다. 월드 로직이 한 스레드에서 도는 것을
전제로 잠금을 두지 않으므로, 운영 명령도 게임 스레드에서 처리해야 한다.

| 값 | 기본 | 비고 |
| --- | --- | --- |
| `SetMaxMembers` | 5 | 2 미만으로는 내려가지 않고 12 를 넘지 않는다 |
| `SetOfferTimeoutSec` | 30 | 초대/퀘스트 공유 제안의 수명 |
| `SetKillCreditRadius` | 60 | 서버 좌표, xz 평면 |
| `SetExpBonusPerMember` | 0.1 | 인원 1명당 총 경험치 보너스 비율 |

## 아직 없는 것

- **전리품(loot) 분배** — 처치 크레딧까지만 있고 아이템 분배 규칙(순서/입찰/획득권)은 없다
- **파티 찾기/공개 모집** — 초대는 화면에서 고른 상대에게만 보낼 수 있다
- **파티 전용 채팅과 위치 표시** — `PartySync` 에 `mapId`/`actorId` 는 실어 보내지만
  클라 UI 는 아직 없다
- **레이드/공대(파티의 파티)** — 인스턴스 입장은 파티 단위가 아니라 개인 단위다
